# 已确认问题

本文仅记录已确认的实现缺陷；功能使用说明见 [使用指南](GUIDE.md)。

## VC-007：侧边回答引用停留在早期流式片段

- 日期：2026-10-05
- 状态：已解决
- 现象：回答已在界面中完成，但引用按钮可能只添加早期片段。
- 原因：按钮闭包保存了首次渲染的消息对象；后续状态使用新对象更新文本，按钮仍引用旧对象。
- 解决方案：点击时按消息 ID 从当前侧边会话读取最新文本，再生成独立快照；校验来源会话未变化。
- 验证：前端定向测试与无头交互检查覆盖消息更新后引用最新回答、旧快照不变。
- 相关文件：`media/app.js`、`test/frontend.test.js`。

## VC-006：无关设置更新重置运行中的选择

- 日期：2026-10-05
- 状态：已解决
- 现象：更改普通讨论模型等无关设置，会把界面选定的只读权限、模型和项目范围重置为设置文件中的默认值。
- 原因：配置事件每次重读全部选项，没有判断具体变更字段。
- 解决方案：仅同步真正变更的字段，项目范围变化单独持久化；无关设置不扩大当前权限。
- 验证：桥接定向测试确认讨论配置不重置只读与范围，明确修改权限配置仍正常同步。
- 相关文件：`extension.js`、`test/bridge.test.js`。

## VC-005：Windows 项目路径形式导致合法目录被拒绝

- 日期：2026-10-05
- 状态：已解决
- 现象：真实 VS Code 宿主中，已经识别的当前目录仍被目录选择逻辑拒绝；编辑器选区发起首个侧边聊天也可能受影响。
- 原因：目录判断直接比较原始字符串，Git 的正斜杠路径与编辑器的反斜杠路径不相等，且未处理 Windows 大小写。
- 解决方案：按运行平台规范化路径后做等值判断，仍只允许已识别的完整目录，返回其规范来源路径。
- 验证：定向测试覆盖分隔符、大小写与相邻目录拒绝；真实宿主重测创建聊天。
- 相关文件：`extension.js`、`test/bridge.test.js`。

## VC-004：显式来源过滤使历史列表读取缓慢

- 日期：2026-10-05
- 状态：已解决
- 现象：本机 Codex 0.160.0 中，同一项目的列表读取使用显式来源过滤耗时约 22.6 秒；省略来源过滤约 1.9 秒。工作台初始化的全局列表曾超时。
- 原因：客户端重复声明了服务端默认涵盖的交互来源，导致本机服务端走较慢的读取路径；上游内部原因不确定。
- 解决方案：依照当前协议默认交互来源读取列表，保留全部模型提供方与分页，不额外限制正常客户端来源。
- 验证：对比本机实际参数请求；定向测试确认分页仍完整、没有重新引入显式来源过滤。真实宿主连接作为集成验证。
- 相关文件：`lib/sessions.js`、`test/backend.test.js`。

## VC-001：异步聊天创建的目标绑定与取消状态

- 日期：2026-10-05
- 状态：已解决
- 现象：创建侧边会话期间切换主聊天，完成时侧栏可能挂到新主聊天；并发引用可能随当前侧栏发送。取消新聊天目录选择后，提交没有结束反馈。
- 原因：异步完成后读取可变的侧边 ID，未核对原主聊天；未创建目标时直接返回。
- 解决方案：创建返回实际侧边会话，引用绑定其 ID；仅在原主聊天仍为当前目标时显示侧栏。取消选择明确报错并保留草稿。
- 验证：桥接定向测试覆盖切换、并发引用和取消后的提交锁释放。
- 相关文件：`extension.js`、`test/bridge.test.js`。

## VC-003：历史列表故障阻断整个工作台

- 日期：2026-10-05
- 状态：已解决
- 现象：历史列表请求失败时，账户与模型也不加载，创建新聊天入口随连接一起失效。
- 原因：初始化把可重试的历史列表读取当作连接成功的前置条件。
- 解决方案：保留协议连接，提示列表读取失败并允许手动刷新，继续加载账户与模型及创建新聊天。上游列表超时的原因尚未确定，本修复不宣称解决上游超时。
- 验证：桥接定向测试模拟列表失败，验证连接、模型、账户与新聊天仍可使用。
- 相关文件：`extension.js`、`test/bridge.test.js`。

## VC-002：新聊天标题不随历史刷新更新

- 日期：2026-10-05
- 状态：已解决
- 现象：新聊天已有内容，列表刷新后仍显示“新聊天”，难以区分会话。
- 原因：缓存会话的默认标题覆盖了历史列表提供的名称或预览。
- 解决方案：刷新时仅将默认标题更新为历史名称或预览，保留自定义名称。
- 验证：桥接定向测试覆盖默认标题更新及自定义名称保留。
- 相关文件：`extension.js`、`test/bridge.test.js`。
